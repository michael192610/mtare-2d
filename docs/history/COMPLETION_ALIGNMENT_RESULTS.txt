COMPLETION ALIGNMENT — 12 November 2026

Only completion logic, its recording/auditing, tests and documentation changed.

Current default rule, checked after fresh global/local plans:
  For each robot: eligible global list empty AND local coverage complete
                  AND logical cycle >300.
  Stop simulation when every robot passes.

Explicit 2D adaptations:
  The simulator has cycles, not physical seconds. The startup guard is >300
  logical cycles, not a 300-second wall wait or a mission time deadline.
  All robots' flags must be true to stop the simulator. Original robot nodes
  report individually and may clear the flag if new work appears.
  Return-home remains excluded. No pursuit/convoy/rendezvous was added.

Removed from default completion:
  Automatic 100% truth-observation exit.
  Additional stable-idle confirmation and map-version stability requirement.
  Additional requirements that every ACTIVE state, path or diagnostic drop count
  disappear. Eligible global work and local completion are the source predicates.

Retained:
  1200-cycle safety cap (recorded stopped, not successfully finished).
  Actual observed percentage reporting, including below-100% outcomes.
  Original settings for VRP, coverage, communications, motion and scheduling.
  Historical prototype modes keep their historical percentage exit.

This change removes extra waiting after planner completion, but cannot guarantee
shorter wall time or fewer cycles. Removing the 100% evaluator exit can make a
run continue longer while the robots still believe useful work remains. It is
closer to the original completion decision rather than a fixed duration limit.
One run validates behavior; it is not a controlled performance comparison.
