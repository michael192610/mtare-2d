LOCAL COVERAGE BOOKKEEPING: IMPLEMENTATION AND VALIDATION
12 November 2026

WHAT IS IMPLEMENTED
Persistent observed/covered ordinary samples; dynamic separate frontier samples;
per-viewpoint ordinary/frontier lists; separate predicted masks; reuse and
navigation preselection; ordinary-first/frontier-second queue selection; marginal
gain updates; local TSP trial choice; separate region-state evidence counts.
Actual covered flags only follow executed/current/historical positions.
Predicted selections and messages do not commit or share detailed coverage.

EXPLICIT 2D TRANSLATION
Free-cell centres are 2 m-spaced ordinary samples. Unknown-side patches near
observed frontiers form the frontier pool without reading hidden occupancy.
Discovery/frontier radius: 7.5 m; ordinary coverage radius: 5 m by default.
The 2/3 ratio is an abstract modeling assumption, not an original M-TARE value.
Small/big ordinary thresholds: 1/2 samples. Frontier minimum/score threshold: 1.
Top-k randomized sampling: 3 (matches original indoor setting); ten ordinary
optimization trials, or one frontier/reuse-only trial. Viewpoint spacing and
region-level count thresholds remain adapted to the sparse 2D grid.

VALIDATION
52 tests passed, including ten new coverage-focused checks. These cover actual
vs predicted coverage, persistent/history flags, hidden-truth independence,
separate scores, reuse/navigation, marginal gains, frontier gates, region-state
feedback, model/radius configuration and planner-work completion below 100%.
Both full-scene simulations passed independent replay audits of committed
coverage from executed positions, frontier pools, every viewpoint score, queue
classification, marginal/top-k selections, masks, trial choice and final counts.
Previous global costs, private-map messages, state transitions, local TSP and
movement checks also passed. A short post-instrumentation run additionally
verified recorded region_coverage_evidence against the actual score lists.

INTERPRETATION
The code now represents the original local coverage decision procedure more
closely, with explicit 2D evidence. The full-comms example used fewer cycles
and less travel than the preceding saved run, but this is a single-seed,
wall-time-limited search comparison. No general performance improvement or
exact equivalence to original M-TARE is established.
Coverage radius, sample spacing, thresholds, coarse connectivity, synchronized
scheduling, target cap and retained evaluator exit remain documented differences.
No separation penalty or forced proposal adoption was introduced.

Historical configuration note: the runs above used the then-default 32-target
cap. The subsequent uncapped baseline uses max_targets = 0. These saved runs
were not modified or rerun, and are not uncapped performance measurements.
